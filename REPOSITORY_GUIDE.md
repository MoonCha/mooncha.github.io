# Repository Guide

This repository contains the source for `https://mooncha.github.io`, a Jekyll
site built with the Minimal Mistakes theme and deployed to GitHub Pages through
a custom GitHub Actions workflow.

## Build Model

The site now uses GitHub Actions as the Pages build source. This means GitHub
serves the generated static files, while the build itself runs in the workflow
defined at `.github/workflows/pages.yml`.

The current workflow:

- runs on pushes to `master`
- can also be started manually with `workflow_dispatch`
- uses Ruby `3.3`
- installs gems with Bundler caching through `ruby/setup-ruby`
- builds with `bundle exec jekyll build`
- uploads `_site` as a Pages artifact
- deploys that artifact with `actions/deploy-pages`

Because the build runs in GitHub Actions, the site can use Jekyll plugins from
the `Gemfile`, including plugins that are not supported by the legacy GitHub
Pages branch builder.

## Theme And Plugins

Theme configuration lives in `_config.yml`.

Current theme setup:

```yml
remote_theme: mmistakes/minimal-mistakes@4.28.0
minimal_mistakes_skin: default
```

The site uses `remote_theme` so both GitHub Actions and GitHub Pages-compatible
build paths can resolve Minimal Mistakes reliably.

Current plugins:

- `jekyll-remote-theme`
- `jekyll-feed`
- `jekyll-sitemap`
- `jekyll-include-cache`

Runtime dependencies are declared in `Gemfile` and locked in `Gemfile.lock`.
When adding or changing plugins, update both files with:

```sh
bundle install
```

Then verify the site locally:

```sh
bundle exec jekyll build
```

## Top-Level Files

- `_config.yml`: main Jekyll site configuration, theme, author metadata,
  plugins, analytics, defaults, and footer scripts.
- `Gemfile`: Ruby gem dependencies for local and Actions builds.
- `Gemfile.lock`: locked gem versions. Commit this after dependency changes.
- `.github/workflows/pages.yml`: custom GitHub Pages build and deploy workflow.
- `index.md`: home page using the Minimal Mistakes `home` layout.
- `blog.html`: notes index page at `/notes/`.
- `topics.html`: category archive page at `/topics/`.
- `404.html`: not found page.
- `robots.txt`: crawler policy and sitemap discovery file.
- `feed.xml`, `sitemap.xml`: generated by `jekyll-feed` and `jekyll-sitemap`;
  do not add handwritten source files with these names.
- `naver757343ff745d16657b17c86c8d4f669c.html`: site ownership verification
  file for Naver Webmaster Tools.
- `LICENSE.md`: repository license.
- `.gitignore`: excludes generated Jekyll build artifacts such as `_site`.

## Jekyll Directories

- `_posts/`: dated blog posts. Files should follow the Jekyll post naming
  pattern `YYYY-MM-DD-title.md`.
- `_data/`: structured site data. Currently contains `navigation.yml`.
- `_includes/`: partial templates. Currently used for custom head content.
- `_layouts/`: local layout overrides or compatibility layouts.
- `_sass/`: local Sass partials, if needed.
- `_sections/`: section-style content carried over from the previous site
  structure.
- `assets/`: stylesheets, JavaScript, images, and other static assets.
- `_site/`: generated build output. Do not edit or commit this directory.
- `.jekyll-cache/`: local Jekyll cache. Do not commit this directory.

## Content Conventions

Posts live in `_posts/` and usually include front matter like:

```yml
---
title: Post Title
description: A concise summary of the post for search results and sharing.
author: MoonCha
layout: post
categories: [DEVELOPMENT]
locale: en-US
last_modified_at: 2026-07-30
header:
  og_image: /assets/images/example.png
  og_image_alt: A meaningful description of the image
---
```

The site-wide locale is `ko-KR`. Add `locale: en-US` only when the primary
content is English. Other languages should use an appropriate BCP 47 language
tag.

The global post defaults in `_config.yml` set most posts to:

- `layout: single`
- `locale: ko-KR`
- `author_profile: true`
- `read_time: true`
- `share: true`
- `related: true`

Some posts may still specify `layout: post`; `_layouts/post.html` maps that to
Minimal Mistakes' `single` layout.

MathJax is loaded from `_includes/head/custom.html` for all posts and for pages
that set `math: true`.

Mermaid support is loaded through:

- `assets/js/mermaid.min.js`
- `assets/js/mermaid-init.js`

These scripts are configured in `_config.yml` under `after_footer_scripts`.

## SEO Maintenance

SEO configuration is distributed across a small number of source files:

- `_config.yml`: site title, description, canonical origin, default locale,
  author identity, global Open Graph image, category archive, plugins, and
  files excluded from publication.
- `_includes/head/custom.html`: robots directives, fallback Twitter card
  metadata, and `BlogPosting` JSON-LD for posts.
- Individual page and post front matter: title, description, locale, social
  image, modification date, and optional indexing controls.
- `robots.txt`: permits crawling and points crawlers to the generated sitemap.
- `topics.html`: crawlable category archive used by post taxonomy links.

### Required Post Metadata

Every indexable post should have:

- A unique, descriptive `title`. Keep the complete rendered title, including
  the site name suffix, reasonably concise.
- A unique `description` that accurately summarizes the page. Do not rely on an
  automatically extracted first paragraph or a heading such as `TL;DR`.
- Relevant `categories`; these create internal links to `/topics/`.
- The correct `locale` when the post is not Korean.
- A representative `header.og_image` and descriptive
  `header.og_image_alt` when a suitable post image exists. Otherwise the
  global image from `_config.yml` is used.
- `last_modified_at` when a published article receives a meaningful content
  update. Do not use the legacy `lastmod` field.

Use meaningful `alt` text for informative images in the article body. Leave
`alt=""` only for images that are genuinely decorative.

### Indexing Controls

Prefer keeping unfinished work outside `_posts/` until it is ready to publish.
If an unfinished page must remain publicly accessible, add both:

```yml
robots: noindex, follow
sitemap: false
```

Remove both values once the article is complete. Machine-readable endpoints,
verification files, and error pages should use `sitemap: false`. The custom
head include renders a `robots` meta tag whenever front matter defines one.

Do not add a custom `sitemap.xml` or `feed.xml`. The configured plugins generate
them from canonical Jekyll URLs and honor `sitemap: false`. Handwritten versions
can omit important pages, publish non-canonical URLs, or provide inaccurate
modification dates.

### Structured Data And Social Metadata

Minimal Mistakes generates canonical, description, Open Graph, and article date
metadata. `_includes/head/custom.html` supplements it with:

- `BlogPosting` JSON-LD for every post
- author and publisher identity
- publication and modification dates
- canonical page identity
- language, categories, and image metadata
- Twitter card metadata when no Twitter username is configured

Keep the JSON-LD values derived from front matter and visible page content.
Never add schema fields for information that is absent from the rendered page.

### Safe URL Changes

Existing post URLs are based on filenames, dates, and categories. Do not rename
a published post, change its date, remove categories, or introduce a new
permalink without preserving the old URL with a redirect. Broken historical
URLs lose backlinks and search equity.

Do not create multiple posts with the same title or substantially duplicate
content. Consolidate overlapping articles or choose clearly distinct search
intent and titles.

### SEO Validation

Before committing SEO or content changes:

1. Run `bundle exec jekyll build`.
2. Confirm `_site/sitemap.xml` contains the homepage, `/notes/`, `/topics/`,
   and every intended indexable post.
3. Confirm draft, verification, error, and machine-readable pages are absent
   from the sitemap.
4. Inspect representative Korean and English HTML pages for the expected
   `lang`, title, description, canonical, `og:image`, Twitter card, and
   `BlogPosting` JSON-LD values.
5. Parse the generated JSON-LD to ensure it is valid JSON.
6. Check that edited images have meaningful alternative text.
7. Review `git status` carefully so untracked drafts and editor files are not
   committed accidentally.

After deployment, spot-check `/robots.txt`, `/sitemap.xml`, and representative
article source on the live site. Submit the sitemap to Google Search Console
and Naver Search Advisor when the sitemap location changes, and use their URL
inspection tools after major metadata or canonical changes.

## Navigation

Main navigation is configured in `_data/navigation.yml`.

Current entries:

- Home: `/`
- Notes: `/notes/`
- Topics: `/topics/`

The notes index is defined by `blog.html` and uses the Minimal Mistakes `posts`
layout. The category index is defined by `topics.html` and uses the Minimal
Mistakes `categories` layout.

## Styling And Assets

The main stylesheet is `assets/css/main.scss`.

It imports:

- the configured Minimal Mistakes skin
- the Minimal Mistakes theme styles
- local syntax highlighting from `assets/css/syntax-highlight.css`

Images used by posts and pages live under `assets/images/`.

The repository also contains older JavaScript and CSS assets from the previous
site design. Keep them until you confirm they are unused by any page or post.

## Deployment Notes

GitHub Pages should be configured with:

- Source: GitHub Actions
- Branch deployment: disabled/not used

With that setting, only `.github/workflows/pages.yml` should deploy the site.
If the legacy `pages build and deployment` workflow appears again, check the
repository Pages settings first.

## Local Workflow

Typical maintenance flow:

```sh
bundle install
bundle exec jekyll build
git status
```

For local preview, use:

```sh
bundle exec jekyll serve
```

Then open the local server URL printed by Jekyll.

## Generated And Local-Only Files

Do not edit generated output in `_site/`.

Do not rely on `.jekyll-cache/` for source changes.

There are local editor and draft artifacts in the working tree at times, such as
`.obsidian/`, untracked draft posts, and temporary diagrams. Review them before
committing so only intentional content enters the repository.
